## Harness-OS-thesis sweep — eight new-to-`seen.json` items, none a scoop

**Headline find: "Transition-Aware Backend Dispatch for Edge LLM Inference"**
(arXiv 2607.17415) — **differentiate-from/cite.** A genuine systems/runtime-
layer contribution: a dispatch policy for edge transformer inference that
combines the current operator's shape features with the previously selected
backend, preserving beneficial backend choices while avoiding costly
device/framework transitions. Evaluated on **real NVIDIA Jetson hardware**
across seven transformer models, three backends (PyTorch eager CPU, PyTorch
eager CUDA, ONNX Runtime CPU), 9,584 ordered operator instances — reduces
latency, energy, and energy-delay product by 17.4%/14.4%/28.5% on average
over the best static policy. This is the closest "runtime makes a
state-dependent dispatch decision, backed by real edge energy telemetry"
precedent found since DVFSLM (iter 39) — structurally the same *shape* of
contribution bigos's own harness-OS framing wants to make (a runtime layer
that adapts to device/workload state), just at the backend-selection layer
rather than the constrained-decoding-mask layer G1 occupies. Not a scoop —
no grammar/mask/schema angle at all — but the strongest citation on file yet
for "runtime-adaptive dispatch policies measurably beat static ones on real
edge hardware," which is close to the paper's own argument shape.

**"The Agent Operating System (AOS): A Reference Operating Architecture for
Distributed Agentic Systems"** (arXiv 2608.03214, Open Compute Project
workstream) — **differentiate-from/cite, naming-relevant.** A vendor-neutral
reference architecture literally named "Operating System" for agentic
systems, with a Control & Governance Plane (intent, policy, trust, audit)
and a Runtime & Coordination Plane (lifecycle, model/tool routing, context/
memory coordination, scheduling). Worth flagging specifically because it
uses the same "OS" framing as bigos, not just "harness" — but it stays at
the application/agent-orchestration level: no edge-hardware constraint, no
SLM-specific claim, no telemetry, no low-level mechanism. Joins the standing
"harness beats model size" naming-precedent cluster (2605.12129, 2602.00887,
2607.08938) as a fourth independent "OS/harness for agents" framing found —
continues to sharpen (not threaten) the requirement that bigos's
contribution be the edge-hardware-mechanism layer these papers all lack.

**"Toward a Modular Architecture for Embedded AI Agent Systems at the Edge"**
(arXiv 2606.02862) — **differentiate-from/cite.** Proposes a tiered
architecture decoupling On-Device Agents (compressed neural nets + rule
logic, low-latency/privacy-critical) from Cloud-Augmented Agents (SLM-based
higher-level reasoning), plus a cross-cutting Governance Layer, explicitly
targeting embedded-microcontroller memory/energy constraints. Closer to
BRIEF.md's own "fleet-of-home-robots" framing than most harness-taxonomy
finds — an architecture-level precedent for the on-device/cloud-tier split
bigos assumes — but still architecture-proposal-level, no energy/latency
measurement, no decode-time mechanism, no grammar/mask angle.

**"AgenTEE: Confidential LLM Agent Execution on Edge Devices"**
(arXiv 2604.18231, EuroMLSys 2026) — **differentiate-from/cite.** Real edge
deployment of confidential agent pipelines: places the agent runtime,
inference engine, and third-party tools into independently attested
confidential VMs (Arm CCA), <5.15% runtime overhead vs. commodity multi-
process deployment. A genuinely different privacy mechanism (hardware
trusted-execution isolation) from bigos's on-device-only-so-nothing-leaves
framing — complementary rather than competing (TEE protects a compromised
*edge* device's own agent pipeline from itself; bigos's privacy story is
about not leaving the device at all). Worth citing as evidence the
"confidential edge agent execution" space is itself active, distinct
mechanism layer from anything G1 or the harness-OS thesis currently claims.

**"SWARM-LLM: Collaborative Inference for Edge-based Small Language Models"**
(arXiv 2606.14711) — **cite.** A routing/collaboration layer coordinating a
swarm of edge-hosted SLMs with an optional cloud foundation model (answer
locally / collaborate with peer SLMs / summon cloud), explicit "on-premises
trust boundary" privacy framing, prototype on commodity hardware with three
heterogeneous SLMs + a 70B cloud model. Resonates with BRIEF.md's own
federated/fleet-of-home-robots candidate axis (Maria's long-standing FL
thread) more than with G1's mechanism — filed as a citation for that axis
specifically, not a competitor to the current harness-OS/G1 scope.

**"SparseDVFS: Sparse-Aware DVFS for Energy-Efficient Edge Inference"**
(arXiv 2603.21908) — **differentiate-from/cite, DVFS sub-thread 5th
member.** Fine-grained, sparsity-aware DVFS: distinguishes compute-bound
dense operators from memory-bound sparse operators, applies specialized
CPU/GPU/EMC frequency triplets via an offline modeler + runtime graph
partitioner + unified co-governor ("FUSE"); 78.17% average energy-efficiency
gain over prior DVFS solutions. Generic DNN framing (not LLM/SLM-specific
in the abstract), but **explicitly models the memory clock (EMC)** —
independently converging with "Edge-Inference Governors Need Memory-Clock
State" (iter 47's headline find, arXiv 2606.16106) that EMC is a governance
factor existing SLM-specific DVFS work (DVFSLM) doesn't model. Extends the
standing DVFS sub-thread to 5 members (DVFSLM 2609.13153, 2507.02135,
2604.15357, 2606.16106, this one).

**"Energy-Efficient GPU DVFS for Fine-Tuning of SLMs on Resource-constrained
