## Literature sweep — correctness-tax cluster (last touched iter 27, most
stale of the three original clusters — 9 members on file)

Four new-to-`seen.json` items, none competitive with G1/Route A, one genuine
mechanism-level find:

- **CRANE — "Reasoning with constrained LLM generation"** (arXiv 2502.09061,
  ICML 2025 poster). The strongest find this iteration, despite predating the
  2026 cluster by over a year (same "foundational precursor found late"
  shape as PSC in the mask-speedup cluster). CRANE gives a *formal proof* —
  via a Turing-machine-simulation argument — for *why* constrained decoding
  loses functional accuracy: a restrictive output grammar that only allows a
  syntactically valid final answer denies the model room to emit the
  intermediate reasoning tokens an autoregressive LM needs for multi-step
  computation. It then fixes this by augmenting the grammar with
  reasoning-preserving rules, gaining up to 10pp accuracy over both
  unconstrained decoding and prior constrained baselines. No edge/hardware
  angle at all. **Differentiate-from** — joins the correctness-tax cluster's
  fix-side (alongside ATLAS-RTC, DCCD) as the clearest *mechanistic*
  explanation on file yet for the correctness-tax gap this loop has been
  citing since iter 7 (arXiv 2605.26128, "The Constraint Tax") — worth a
  stronger related-work sentence than the purely empirical correctness-tax
  papers get, since it explains the "why," which the harness-OS paper's own
  correctness-grading-gate argument can lean on.
- **Constraint Decay: The Fragility of LLM Agents in Backend Code
  Generation** (arXiv 2605.06445). A name collision, not a competitor: this
  "constraint" means software-architecture requirements (framework/ORM/DB
  choice) in agentic backend code generation, not token-level grammar/schema
  decoding constraints. **Ignore**, filed only to prevent re-discovery under
  a title that superficially matches the cluster's vocabulary.
- **DINGO: Constrained Inference for Diffusion LLMs** (arXiv 2505.23061,
  NeurIPS 2025). A provably distribution-preserving constrained-decoding
  algorithm, but for diffusion (parallel, non-autoregressive) LLMs — a
  different generation paradigm from the harness's llama.cpp/Ollama
  autoregressive target. **Ignore**, same shape as LAVE (iter 25, diffusion
  decoding), filed to avoid re-discovery.
- **The LLM Data Auditor: A Metric-oriented Survey on Quality and
  Trustworthiness in Evaluating Synthetic Data** (arXiv 2601.17717). About
  auditing LLM-generated *training data*, not constrained-decoding
  correctness or edge systems — surfaced only by keyword overlap
  ("trustworthiness," "LLM-generated"). **Ignore**.

Net effect: the correctness-tax cluster's problem-side headline claim (arXiv
2605.26128, "The Constraint Tax") now has a formal mechanism explanation
(CRANE) to cite alongside it, which strengthens rather than threatens the
harness-OS paper's planned correctness-grading gate — still nobody combines
this with edge-hardware latency/energy telemetry or a mitigation mechanism
at the decode/kernel level, which is what G1 + the correctness gate together
would supply.
