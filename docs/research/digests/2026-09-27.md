## Correctness-tax cluster — seven new-to-`seen.json` items

1. **"Repair, Not Improvement: Decomposing Constrained Decoding in Tool-Call
   Abstention"** (arXiv 2608.13959, submitted 2026-08-14) — **differentiate-from/cite.**
   Evaluates open-weight models **0.6B–4B — Maria's own model class** — on
   tool-call *abstention* (declining to call anything when no tool applies,
   not just picking the right tool). Grammar-constrained decoding over the
   declared tool names is a large accuracy win for the pick-a-tool case on
   small models, but the paper's own framing ("repair, not improvement")
   argues this doesn't extend cleanly to the abstain case: an enum over tool
   names restricts which answers *exist*, and the answer most likely to get
   deleted by that restriction is the "no tool applies" one. Sharpens the
   cluster's core finding (schema-valid ≠ correct) into a specific, testable
   failure mode — worth remembering for any future tool-calling harness eval
   that includes a legitimate no-tool-applies case, which several of Maria's
   own agent schemas do.
2. **"When JSON Is Not Enough: Semantic Reliability of Schema-Constrained
   LLM Ordering Agents"** (arXiv 2607.18261, Univ. of Birmingham) —
   **differentiate-from/cite.** OrderBench, a restaurant-ordering-agent
   benchmark separating syntactic/schema validity from status decisions,
   exact item semantics, constraint preservation, and unsafe acceptances.
   Across 2,400 calls to four open models (cloud API), the strongest model
   hits 100% schema validity in both prompt-only and JSON-schema modes but
   only ~80% semantic success; weaker models show double-digit
   schema-valid-but-*unsafe* acceptances. Another independent domain
   (agentic transactions) confirming the cluster's central claim; cloud-API
   models, no edge/latency/energy angle.
3. **"Don't Adapt Small Language Models for Tools; Adapt Tool Schemas to the
   Models"** / **PA-Tool** (arXiv 2510.07248, ACL 2026) —
   **differentiate-from/cite.** A training-free fix: rename tool-schema
   components to match what a small model already knows from pretraining
   (using a peakedness/contamination-detection signal), instead of
   fine-tuning the model to an unfamiliar schema. Up to 17% improvement on
   MetaTool/RoTBench, 80% fewer schema-misalignment errors. Genuinely
   different fix mechanism from the cluster's usual decode-time-masking
   fixes (CRANE/GAD/AprAD/DCCD/DOMINO) — this one is a *pre-decode
   schema-wording* fix, joining schema-key-wording (2604.14862) and
   schema-descriptions (2608.08254) as a third "how you phrase the schema
   matters" mechanism. Explicitly targets small models; no edge-hardware
   angle.
4. **"Don't Fine-Tune, Decode: Syntax Error-Free Tool Use via Constrained
   Decoding"** / **TOOLDEC** (arXiv 2310.07075, 2023) — **differentiate-from,
   lineage.** A pre-2026 foundational precursor for grammar-constrained
   tool-call decoding, predating the cluster by ~3 years. A fifth
   "foundational-precursor-found-late" case (joins CRANE/GAD/AprAD/DOMINO);
   filed for lineage completeness, not an active competitor.
5. **"Projectional Decoding: Towards Semantic-Aware LLM Generation"**
   (arXiv 2605.30054) — **ignore.** Software-engineering-artifact domain
   (maintains a partial graph model alongside text for semantic validation
   of generated *software artifacts*), not JSON/tool-call schemas. Filed to
   avoid re-discovery via keyword overlap ("semantic", "constrained
   decoding").
6. **ATLAS: A Layered Constraint-Guided Framework for Structured Artifact
   Generation in LLM-Assisted MDE** (arXiv 2510.25890) — **ignore.**
   Automotive/AUTOSAR model-driven-engineering domain — wrong field
   entirely, same class as ARCS (iter 42, EDA domain). **Name-collision
   note:** this "ATLAS" is unrelated to the already-tracked ATLAS-RTC
   correctness-tax fix-side paper — do not conflate on a future "ATLAS"
   keyword hit.
7. **"Semantic Probabilistic Control of Language Models"** (arXiv 2505.01954)
   — **ignore.** A different sense of "semantic control" entirely — steers
   generation toward non-lexical attributes (toxicity, sentiment,
   politeness) via verifier-gradient reweighing, not schema-validity-vs-
   correctness. Filed to avoid re-discovery via "semantic control"/
   "constrained" keyword overlap.
