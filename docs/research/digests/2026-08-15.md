Route A's recommended first step (`FINAL-strategy-routes.md`) is a one-evening
smoke test: llama.cpp's multimodal tool (`mtmd`) running a vision model with a

  smoke test is a config exercise, not new engine work. (Sources:
  [llama.cpp mtmd README](https://github.com/ggml-org/llama.cpp/blob/master/tools/mtmd/README.md),

## Part 2 — New literature (2 items, neither a scoop)

1. **["Edge-Deployed Lightweight LLMs for Medical Imaging: Real-Time Dual
   Report Generation with Progression Aware Summarization"](https://dl.acm.org/doi/10.1145/3796263.3796284)**
   (ACM ICCRD 2026). Same use-case neighborhood as Route A (on-device VLM
   generating structured medical reports from imaging) but a different
   mechanism entirely: their method is distillation/pruning/quantization to
   shrink the model for edge deployment, generating a "dual report" (clinical
   + patient-facing). No mention of grammar/schema-constrained decoding, no
   energy-per-token or mask-cost measurement. **Verdict: differentiate-from**
   — worth one related-work sentence if Route A goes forward ("prior work
   compresses the model; we instead characterize and fix a decode-time tax
   that survives compression"), not a scoop of the constrained-decoding-tax
   claim. Full text is behind the network egress block (dl.acm.org), read
   from search snippet only — flag for a manual check once network access
   allows, since it's the closest-yet paper to Route A's exact use case.

2. **["Accelerating Constrained Decoding with Token Space
   Compression"](https://arxiv.org/pdf/2605.29986)** — a general (non-edge,
   non-VLM) technique for speeding up grammar-constrained decoding by
   compressing the token space the grammar has to mask over. Same problem
   family as G1's mechanism (grammar mask construction cost) but a different
   fix (token-space compression vs. G1's shadow-mask CPU/GPU pipelining) and
   no edge-hardware or energy measurement. **Verdict: cite** — a real
   alternative-mitigation citation for the eventual paper's related work,
   regardless of which route is chosen; not competitive with the specific
   pipelining method.

`LiteVLM` (2506.07416, low-latency VLM pipeline via patch selection/token
compression/speculative decoding) also surfaced but targets prefill/vision-
encoder cost, not grammar-constrained decode — same conclusion as prior
iterations' read of the "Seeing is Free, Speaking is Not" thread: decode-time
constrained-generation cost on edge VLMs remains unmeasured in the literature
found so far. No change to the blue-ocean read in `FINAL-strategy-routes.md`.
