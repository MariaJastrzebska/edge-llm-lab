## Correctness-tax cluster sweep — six new-to-seen.json items, one new
fix-side mechanism precursor, two data-hygiene fixes

Four queries ("constrained decoding accuracy tax grammar structured output
correctness," "schema-constrained decoding accuracy degradation LLM,"
"structured output LLM accuracy loss fix August/September 2026," and a
targeted author/title lookup for each new hit). Most results were already
in `seen.json` (The Constraint Tax 2605.26128, The Format Tax 2604.03616,
Thinking Before Constraining 2601.07525, DCCD 2603.03305, When Correct Isn't
Usable 2605.02363, Grammar-Aligned Decoding 2405.21047) — no change to those
entries. Six genuinely new items:

- **Approximately Aligned Decoding / AprAD** (arXiv 2410.01103, Amazon,
  Oct 2024) — **differentiate-from/cite**. A speculative-decoding-inspired
  fix that resamples toward the unconstrained distribution instead of hard
  masking, explicitly trading distortion against compute cost — a genuine
  mechanism-level fix predating the 2026 correctness-tax cluster by over a
  year, never entered until now. Same "foundational-precursor-found-late"
  shape as CRANE (iter 34), Grammar-Aligned Decoding (iter 37), SynCode
  (iter 37), and PSC (iter 29/2) — joins the cluster's fix-side as a fourth
  independent mechanistic angle (grammar-distribution resampling, distinct
  from CRANE's reasoning-token-starvation account and GAD's
  distribution-correction account). No edge/Joules angle.
- **Quantifying the Impact of Structured Output Format via Causal
  Inference** (arXiv 2509.21791, EACL 2026 Findings) — **differentiate-from/
  cite**. Applies causal-inference methodology (rather than correlational
  benchmarking) to resolve the standing "does structured output help or
  hurt?" disagreement in the literature — a methodologically stronger
  confirmation of the correctness-tax problem-side, no edge angle.
- **Empirical Study for Structured Output Control in LLMs for Software
  Engineering** (arXiv 2606.09395) — **differentiate-from/cite**. Benchmarks
  grammar-constrained decoding, regex validation, and a strict
  template-driven control (TTMG) across four SE tasks; finds TTMG nearly
  eliminates syntax errors but structural/semantic errors persist —
  independent domain replication (software engineering, not medical/JSON)
  of the same validity-vs-correctness split this cluster already
  documents, no edge angle.
- **Where vs What: Decomposing Structural and Content Failures in
  LLM-Generated Structured Outputs** (arXiv 2608.25358) — **differentiate-
  from/cite, methodology-relevant**. Introduces Structure-Content
  Decomposition (SCD): separately measuring placement errors (right value,
  wrong position) from value errors (wrong value), finding structural
  fidelity degrades earlier than content accuracy as schema complexity
  grows. Directly relevant methodology for the harness-OS paper's own
  planned correctness-grading gate (open debt item, DECISIONS.md
  2026-08-14 #3) — worth reaching for when that grading code gets written,
  not just a citation.
- **Your Prompt Is Not the Only Prompt: How Much Do LLMs Weight
  Structured-Output Schema Descriptions?** (arXiv 2608.08254) —
  **differentiate-from/cite**. Shows schema descriptions act as a second,
  sometimes-dominant instruction channel that can override prompt
  instructions (accuracy drops of 5-45pp on conflict) — a third distinct
  correctness-tax mechanism family (prompt/schema-authoring, not decode-time
  grammar restriction), joins schema-key-wording (2604.14862, iter 9) on
  that side of the cluster.
- **The Architecture of Errors: From Universal Impossibility to Patch-Local
  LLM Reliability** (arXiv 2605.30628) — **ignore**. A general LLM-reliability
  theory paper (impossibility results for universal reliability vs.
  tractability within a fixed deployment "patch"); not specifically about
  grammar/schema-constrained decoding or structured-output correctness —
  surfaced only by keyword overlap on "reliability." Filed to avoid
  re-discovery, no cluster relevance.

**Two data-hygiene fixes** (same class as iters 22/29/31/32/33/36/38): two
entries had sat in `seen.json` as bare dates since iteration 1-2 with no
annotation.
- **JSONSchemaBench** (arXiv 2501.10868, Jan 2025) — now annotated,
  **differentiate-from/cite, methodology-relevant**. A 10K-schema benchmark
  evaluating six constrained-decoding frameworks (Guidance, Outlines,
  **llama.cpp**, XGrammar, OpenAI, Gemini) on efficiency/coverage/quality —
  directly useful as a related-work citation since it benchmarks the same
  grammar engine family (llama.cpp/GBNF) this lab's harness drives, though
  its "efficiency" axis is wall-clock/throughput on commodity GPUs, not
  edge-hardware energy — not a competitor, no edge measurement.
- **Attention Meets Reachability: Structural Equivalence and Efficiency in
  Grammar-Constrained LLM Decoding** (arXiv 2603.05540) — now annotated,
  **differentiate-from**. A theoretical framework (oracle-invariance
  theorem: language-equivalent grammars yield identical token-admissibility
  sets) for the *algorithmic mask-speedup cluster*, not the correctness-tax
  cluster — a foundational/lineage paper for that cluster's efficiency
  claims, no cluster-count change (theoretical precursor, not a numbered
  member), no edge/Joules angle.
