## New-to-seen.json items

1. **Externalization in LLM Agents: A Unified Review of Memory, Skills, Protocols and
   Harness Engineering** (arXiv 2604.08224, Apr 2026, 21 authors) — a large survey that
   names "harness engineering" as the unification layer coordinating memory/skills/
   protocols in LLM agents. **Cite** — useful precedent that "harness" is becoming a
   named, citable engineering category in the agent literature (supports bigos's own
   "Harness OS" framing terminologically), but purely application/agent-orchestration
   level: no edge-hardware deployment, no SLM-specific claim, no energy/latency
   telemetry, no low-level mechanism. Does not compete on the paper's actual
   contribution.

2. **Architectural Design Decisions in AI Agent Harnesses** (arXiv 2604.18071, Apr
   2026) — protocol-guided empirical study of 70 public agent-system projects,
   identifying five recurring harness design dimensions (subagent architecture,
   context management, tool systems, safety mechanisms, orchestration). **Differentiate-
   from** — same shape as #1: a harness-taxonomy paper at the software-architecture
   level, no edge/SLM/telemetry angle. Useful as "harness design is a studied object"
   background, not a threat.

3. **AutoHarness: improving LLM agents by automatically synthesizing a code harness**
   (arXiv 2603.03329, Feb 2026) — Gemini-2.5-Flash auto-synthesizes a code harness that
   prevents illegal moves in 145 TextArena games, letting a smaller model beat a larger
   one. **Ignore** — different sense of "harness" (auto-generated rule-enforcement code
   for game legality), no edge/hardware/SLM-systems angle.

4. **Evo-Harness: Context-to-Harness Skill Compilation for Self-Evolving Agents**
   (arXiv 2608.15071, EMNLP 2026) — online harness learning that compiles execution
   contexts into reusable skill-harness updates, evaluated on Terminal-Bench/SWE-bench/
   WebArena-Infinity. **Ignore** — agent self-improvement/skill-compilation, cloud-scale
   benchmarks, no edge or hardware-cost dimension.

5. **To Know is to Construct: Schema-Constrained Generation for Agent Memory /
   SCG-MEM** (arXiv 2604.20117, Apr 2026) — uses schema-constrained decoding to
   generate valid memory-lookup keys for LLM-agent memory systems, avoiding
   "structural hallucination." **Ignore** — a genuine constrained-decoding application,
   but for memory retrieval correctness, not edge deployment or decode-cost; no
   latency/energy claim at all.

  Model on Edges** (arXiv 2511.11624) — benchmarks 5 SLMs (Llama 3.2, Phi-3 Mini,
  TinyLlama, Gemma 2) for power efficiency across **Raspberry Pi 5, Jetson Nano, and

  touch mechanism at all).
- **Constraint Tax in Open-Weight LLMs: An Empirical Study of Tool Calling Suppression
  Under Structured Output Constraints** (arXiv 2606.25605) — documents "Tool
  Suppression": open-weight models silently stop invoking tools when tool-calling and
  JSON-schema constraints are enabled jointly, even though schema compliance and tool
  execution each work fine independently when tested in isolation. A **distinct**
  correctness-tax mechanism from the Format Tax / Constraint Tax validity-vs-accuracy
  tradeoff already on file — joins the correctness-tax cluster's problem side as
  another independent demonstration that constrained decoding has real, non-obvious
  behavioral costs beyond schema validity. Reinforces (does not newly open) the
  standing correctness-tax gap.
