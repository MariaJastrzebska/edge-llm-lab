## New-to-seen.json items (6)

1. **"Efficient Deployment of Vision-Language Models on Mobile Devices: A Case Study on
   OnePlus 13R"** (arXiv 2507.08505, EPFL) — **headline find.** Real-phone deployment
   study evaluating **llama.cpp**, MLC-Imp, and mllm running LLaVA-1.5-7B, MobileVLM-3B,
   and Imp-v1.5-3B on a OnePlus 13R, with CPU/GPU/NPU utilization profiling. Finds
   consistent CPU overutilization during decode, GPU/NPU underutilization, and GPU-offload
   attempts causing device instability (screen freezes). **Verdict: differentiate-from/cite.**
   This is the closest "our own engine (llama.cpp), a VLM, on a real edge device, with
   telemetry" precedent found for the harness-OS thesis's planned VLM extension —
   directly relevant groundwork for Route A regardless of which way Maria's sub-question
   #3 (starting use case) lands. No grammar/mask angle — it doesn't touch constrained
   decoding, so not a scoop of G1's mechanism.
2. **StepX-Edge: An On-Device UI Vision-Language Model via Architecture-Training-Deployment
   Co-Design** (arXiv 2607.22708, ICMI 2026 CC-MMD Grand Challenge) — differentiate-from/cite.
   A 0.9B on-device UI-grounding VLM, real Snapdragon 8 Gen5 deployment after W4A16+KV8
   quantization: 0.84s time-to-first-token, 98 tok/s decode, 1.4GB peak memory. Another
   real-phone VLM-deployment telemetry precedent (joins 2507.08505 above), UI-automation
   domain not medical/robotic, no grammar/mask angle.
3. **"From Generalist to Specialist: A Context-Fusion Framework for Endoscopic Polyp
   Reporting with a Frozen VLM"** (arXiv 2608.15580) — differentiate-from/cite. A frozen
   general-purpose VLM is prompted (via retrieved image-report evidence + learned
   continuous "specialist tokens," no weight updates) to emit a single structured JSON
   report per polyp: diameter, Paris classification, morphological description. The
   closest medical-structured-VLM-JSON-report precedent found in a while — converges
   with Route A's exact use-case shape (VLM → structured clinical JSON) — but no edge
   deployment and no grammar-constrained decoding (structuring is prompt-based, not
   decode-time masking), so not a mechanism competitor.
4. **EndoVLM: An Endoscopy Vision-Language Pre-training Model via Anatomy-Guided Sparsity
   and Progressive Alignment** (arXiv 2608.04472) — **ignore.** A representation-learning/
   pretraining model (anatomy-guided sparse frame pooling + progressive semantic alignment
   over 348K exams), not a structured-report-via-decoding system, no edge angle. Continues
   the standing pattern (since iter 10) that medical/surgical-VLM literature has zero
   systems-cost competitors.
5. **A Survey on Efficient Vision-Language Models** (arXiv 2504.09724) — filed, no
   discussion. Background survey, predates the 2026 cluster by roughly a year (Apr 2025).
6. **A Contemporary Overview: Trends and Applications of Large Language Models on Mobile
   Devices** (arXiv 2412.03772) — filed, no discussion. General mobile-LLM survey,
   Dec 2024, not VLM-specific.
