## Harness-OS-thesis sweep — no direct competitor, several telemetry-
methodology precedents, one data-hygiene fix

Queries covered: general "SLM inference harness/runtime edge systems"
phrasings, a decode-time-mechanism-specific phrasing, a follow-up on named

1. **LEAF** (MDPI *Machine Learning and Knowledge Extraction*,
   doi:10.3390/make8020048, published 2026-02-18) — differentiate-from/cite.
   Real hardware: Raspberry Pi 4/5 and Jetson Nano plus desktop NVIDIA
   T400/legacy GPUs, 4-bit quantized models served via **Ollama** (the
   lab's own model-registry engine), introduces sustainability metrics
   (Circular Economy Score, Energy-per-Token) alongside latency/accuracy.
   Same telemetry-methodology shape as lm-Meter/ELIB-MBU/Sustainable-LLM-
   Inference-for-Edge-AI — a fourth independent Jetson-family data point and
   a new Raspberry Pi 4/5 one, for whenever the postponed Jetson purchase
   (sub-question 5) resurfaces. Not on arXiv (journal DOI only), so it did
   not surface in prior arXiv-only sweeps.
2. **Code-SLM serving-configuration energy study** (arXiv 2412.15441,
   "Insights into resource utilization of code small language models
   serving with runtime engines and execution providers") — differentiate-
   from/cite. Real energy/latency/compute measurements across 12 code-
   generation SLMs × multiple runtime-engine/execution-provider
   combinations (ONNX Runtime, etc.), finds serving configuration alone can
   cut inference energy up to 89%. Directly on point for the harness-OS
   thesis's core claim — that runtime/serving-layer choices materially
   change SLM inference cost — though it's ONNX Runtime not llama.cpp and
   has no grammar/mask angle.
3. **Network Edge Inference for LLMs** (arXiv 2604.22906) — cite. Broad
   survey (system architectures, model optimization/deployment, resource
   management/scheduling) for LLM inference at the network edge — related-
   work anchor, no mechanism of its own.
4. **A Survey on Collaborating Small and Large Language Models** (arXiv
   2510.13890) — cite. Covers the whole edge-cloud collaborative-inference
   space in one place (the DynaSplit/CoVSpec/INAR-VL/LAST/SLED/Token-Level-
   Routing family already on file) — useful as a single related-work anchor
   for that cluster going forward instead of citing each split-computing
   paper individually.
5. **Large Models for Small Devices** (arXiv 2608.15693) — cite, background
   survey, continues the standing pattern that survey literature here stays
   broad/characterization-level.
6. Three more edge-cloud-dependent papers scored **ignore**, all the
