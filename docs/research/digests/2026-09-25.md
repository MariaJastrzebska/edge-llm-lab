## New-to-seen.json items

1. **Edge-Inference Governors Need Memory-Clock State** (arXiv 2606.16106,
   Jaehoon Kang, submitted Jun 2026, v3 Jul 2026)
   Link: https://arxiv.org/abs/2606.16106
   Relevance: frequency-aware latency estimators for deadline-aware DVFS
   governors model latency over CPU/GPU clocks but not the memory clock
   (EMC) — on a real **Jetson Orin**, an EMC-blind GPU-only fit misses
   25–28% of cycles at tight deadlines; an EMC-aware two-cell refit holds
   misses to ≤0.9% under a 2% QoS budget. Also models decode-horizon
   (KV-cache growth vs. deadline feasibility) and GPU co-tenancy
   (queueing tails), with a contract-admission policy composing all three
   layers.
   Verdict: **differentiate-from/cite — headline find this iteration.**
   The strongest harness-OS-thesis citation since DVFSLM (iter 39): a
   genuine runtime/kernel-layer governance mechanism, real edge hardware,
   directly extends the DVFS sub-thread (DVFSLM 2609.13153, the
   characterization precursor 2507.02135, the latency-estimation paper
   2604.15357) with a factor DVFSLM's own governor doesn't model. Not a
   scoop of G1 (memory-clock/deadline governance vs. constrained-decoding
   mask-cost tax + shadow-mask pipelining — different mechanism layer
   entirely) — but the DVFS sub-thread is now four papers deep and worth a
   dedicated related-work paragraph if the paper scope resolves toward
   "whole harness" (sub-question 1).

2. **Transferable Latency Prediction for Fast LLM Screening on
   Heterogeneous Edge Devices** (arXiv 2607.21602, Tu/Mishra/Dasari/
   Bourgeois/Wang, submitted May 2026)
   Link: https://arxiv.org/abs/2607.21602
   Relevance: runtime-aware latency-prediction framework for
   deployment-oriented LLM selection — represents each inference request
   as a hardware/runtime/model/prompt configuration, separates
   prefill/decode phases, fuses static descriptors with dynamic hardware
   telemetry (including DVFS state and thermal variation) via a gated
   prediction model. Evaluated on real hardware: Pixel phones, Jetson
   Nano, Orange Pi 5 Pro, and an RTX 3090-class GPU.
   Verdict: **differentiate-from/cite** — a telemetry-methodology
   precedent joining the DVFS/thermal-aware-prediction sub-thread (same
   shape as lm-Meter, "Taming Asynchronous CPU-GPU Coupling"), no
   grammar/mask angle, model-*selection* framing rather than a runtime
   mechanism.

3. **Triple-Bottom-Line Sustainability of Language Models for Edge AI: A
   Comparison Between SLMs and Quantized LLMs** (arXiv 2609.00665, Jainil
   Dharmil Shah, Purdue, submitted Sep 2026)
   Link: https://arxiv.org/abs/2609.00665
   Relevance: a reproducible Holistic Sustainability Score (economic +
   environmental/GPU-energy + social/harmful-prompt-robustness pillars)
   comparing 5 natively-trained SLMs against 5 LLMs under BF16/INT8/NF4/
   GPTQ/GGUF-Q4 quantization — 30 measured configurations, real GPU energy
   measurement.
   Verdict: **differentiate-from/cite** — a telemetry-methodology
   precedent (same shape as LEAF/lm-Meter/Sustainable-LLM-Inference-for-
   Edge-AI), quantization mechanism not constrained decoding, and directly
   relevant to the SLM-vs-quantized-LLM framing question that sits behind
   Maria's own model-selection choices. No edge-CPU/embedded hardware
   (GPU-only), no grammar/mask angle.

4. **From Retrieved Context to Runtime Control: Adaptive Compression for
   Edge-based RAG** (arXiv 2608.19535, Feric/Taherin/Wang/Kaeli, ACM AI
   Leadership Summit 2026)
   Link: https://arxiv.org/abs/2608.19535
   Relevance: telemetry-informed *adaptive* context compression for
   edge RAG — a runtime-control mechanism that responds to live device
   state (memory traffic, latency, energy) rather than a fixed offline
   compression budget; characterized on a real **NVIDIA Jetson AGX Thor**
   with Llama/Qwen generators.
   Verdict: **differentiate-from/cite** — different task entirely (RAG
   context compression, not constrained decoding), but the same
   *shape* of contribution the harness-OS paper is making: a runtime
   mechanism that adapts to live edge-device telemetry rather than a
   static policy, validated on real hardware. Worth a sentence in
   related work distinguishing "runtime-adaptive-to-device-state"
   mechanisms across different sub-layers (RAG context budget here, mask
   computation for G1) if the whole-harness scope is confirmed.
