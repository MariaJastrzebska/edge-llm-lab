## New-to-seen.json items (4)

1. **Correctness-Guaranteed Code Generation via Constrained Decoding**
   (arXiv 2508.15866, COLM 2025) — a context-sensitive parser that emits a
   regex at each decoding step to guarantee one-shot *semantic* correctness
   for a typed scripting language (sLua), demonstrated on generating
   roguelike game mechanics. **Verdict: ignore.** Code-generation domain
   (continues the standing pattern of 2504.09246, 2606.25987 scored the
   same way) — no edge hardware, no latency/energy measurement, no
   grammar-*mask-cost* angle. Not competitive with G1/Route A.

2. **AdapTrack: Constrained Decoding without Distorting LLM's Output
   Intent** (arXiv 2510.17376, ICSE 2026) — adds backtracking to
   constrained decoding for code/API completion so the model isn't forced
   down a schema-valid-but-intent-violating path; up to 360.87% improvement
   on synthetic API-completion benchmarks. **Verdict: ignore.** Same
   code-gen-domain pattern as above — this is a correctness-tax *fix-side*
   idea (avoid distortion) but scoped to software-engineering code
   generation, not edge/schema/JSON inference. Not competitive.

3. **lm-Meter: Unveiling Runtime Inference Latency for On-Device Language
   Models** (arXiv 2510.06126, ACM/IEEE SEC 2025) — a lightweight, online,
   kernel-level latency profiler for on-device LLM inference (phase-level:
   embedding/prefill/decode/softmax/sampling), validated on commercial
   mobile hardware with <3% profiling overhead. **Verdict: differentiate-
   from / cite.** No grammar/mask-cost angle at all, so not competitive —
   but it's the closest-yet paper to the *measurement methodology* side of
   this lab's own harness (phase-level on-device latency instrumentation).
   Worth a related-work sentence on the instrumentation side if Route A's
   paper discusses its own telemetry design, not a threat to the
   scientific claim.

4. **Sustainable LLM Inference for Edge AI: Evaluating Quantized LLMs for
   Energy Efficiency, Output Accuracy, and Inference Latency** (arXiv
   2504.03360, ACM Trans. Internet of Things) — benchmarks 28 quantized
   Ollama models on a Raspberry Pi 4 (4GB) across energy/accuracy/latency
   using hardware-based power measurement. **Verdict: differentiate-from /
   cite.** Mechanism is quantization bit-width, not constrained decoding —
   zero overlap with G1/Route A's per-token-mask-cost claim — but it's
   directly adjacent on hardware class (Ollama + edge SBC) and measurement
   style (real hardware energy meters, not estimators), same shape as the
   already-filed CO2-Meter citation (iter 9): citable methodology
   precedent, not competitive pressure.
