## Main task: does anyone do CPU-only mask pipelining (not CPU/GPU)?

Iter 18 found that "Challenging GPU Dominance" (2505.06461) shows llama.cpp
on an iPhone 15 Pro running a 1B model faster CPU-only than GPU-accelerated —
which breaks the assumption behind XGrammar's known CPU-mask/GPU-forward-pass
pipelining trick (there's no separate GPU resource to hide the mask
computation under). Iter 19's queued question: does any published work
propose overlapping mask computation with the forward pass itself when both
run on CPU (e.g. across CPU cores, or CPU + ANE/NPU) for exactly this
CPU-decode regime?

**Result: no direct hit — this specific mitigation is not published, as far
as this sweep can tell.** Every CPU-offload/CPU-GPU-overlap paper found
assumes a GPU forward pass as the resource being hidden under; none address
mask-vs-forward-pass overlap when the forward pass is itself CPU-bound. This
is a **negative result that helps Route A's novelty case**, not a dead end —
the open gap iter 18 surfaced stays open and unclaimed by anyone else found
so far.

**New-to-`seen.json` items found via this check (2):**
1. **NEO: Saving GPU Memory Crisis with CPU Offloading for Online LLM
   Inference** (arXiv 2411.01142, MLSys 2025 poster) — **ignore.** CPU
   offloads attention compute + KV-cache to increase GPU batch size for
   cloud serving throughput (up to 7.5× on T4). Tested on T4/A10G/H100 —
   data-center GPUs, batched multi-request workload, no grammar/mask angle
   at all. Same shape as the already-tracked batch-serving cluster
   (Pre³/XGrammar-2/APEX): another entrant that's CPU/GPU-overlap-flavored
   but squarely on the cloud-serving side, not edge single-stream.
2. **Ghidorah: Fast LLM Inference on Edge with Speculative Decoding and
   Hetero-Core Parallelism** (arXiv 2505.23219) — **differentiate-from /
   cite.** On-device, unified-memory end-user hardware — and tested
   specifically on **NVIDIA Jetson NX** (the exact device class Route A's
   planned-but-postponed Jetson replication leg would use). Combines
   speculative decoding with hetero-core model parallelism (HCMP):
   distributing draft/verify work across CPU/GPU/NPU concurrently to hide
   the memory-bandwidth bottleneck, claims 7.6× decode speedup vs. sequential
   on Jetson NX. Not a grammar-masking paper and doesn't answer iter 19's
   question directly, but two things worth carrying forward: (a) it's direct
   evidence that heterogeneous-core concurrent utilization is an active,
   effective strategy on Route A's own target deployment hardware — good
   reviewer-defense ammunition alongside BaseRT (iter 11) for "this hardware
   class is a live optimization target"; (b) its HCMP technique (assigning
   different pipeline stages to different cores based on profiled
   architecture) is a plausible template for the still-unsolved CPU-decode
   mask-pipelining design — e.g. mask computation on one CPU core/cluster
   while decode runs on another core or the NPU, profiled per-device the way
   ARCA does for speculative decoding. Worth a related-work sentence and a
   design-inspiration note if/when Route A's mechanism design gets built.
