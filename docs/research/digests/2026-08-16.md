## 2. New items this iteration

### Correctness-tax cluster (reinforces the open gap, not a scoop)

1. **"The Hidden Cost of Structured Generation in LLMs: Draft-Conditioned
   Constrained Decoding" (DCCD)** — arXiv 2603.03305 (Reddy, Walker, Ide,
   Bedi; Feb 2026).
   Relevance: shows token-by-token grammar masking can push generation toward
   *locally valid but semantically wrong* trajectories — i.e. an accuracy
   cost from constraining, not just a latency one. Proposes generating an
   unconstrained draft first, then constraining conditioned on it (+24pp
   strict-structured-accuracy on GSM8K with a 1B model). No edge hardware, no
   latency/energy measurement — it's an accuracy-only, cloud-scale study.
   **Verdict: cite.** This is direct outside evidence for the correctness-tax
   gate already flagged open since iteration 7 ("005/006 measure schema
   validity, not answer correctness — arXiv 2605.26128 shows the two can
   diverge sharply on this exact task shape"). DCCD is a second, independent
   paper making the same point with a different mechanism name and a
   candidate fix — strengthens the case that Route A/G1 needs the
   correctness-grading gate before any "constrained decoding is harmless"
   claim, and gives a concrete method (DCCD) to cite or benchmark against once
   that gate exists. Does not compete with G1/Route A's actual contribution
   (hardware-level mask/pipelining latency-energy cost on edge SoCs).

2. **"Schema Key Wording as an Instruction Channel in Structured Generation
   under Constrained Decoding"** — arXiv 2604.14862 (Yifan Le, Apr 2026).
   Relevance: shows schema-key *wording* alone (not the prompt, not the
   model) measurably shifts reasoning accuracy under constrained decoding —
   model-dependent (Qwen leans on schema-level instruction, LLaMA leans on
   prompt-side guidance). Same cluster as DCCD: accuracy effects of
   constrained decoding, no edge/hardware/latency angle.
   **Verdict: cite** as a secondary correctness-tax reference, and a
   practical warning for whichever route ships a real schema (Route A's
   clinical-report schema, Route D's medical JSON): key-wording choices are
   not neutral and should be controlled for in the correctness-grading
   design once that harness change happens.

### Energy/carbon-on-edge cluster (adds to the already-crowded pressure list, non-overlapping)

3. **DynaSplit: A Hardware-Software Co-Design Framework for Energy-Aware
   Inference on Edge** — arXiv 2410.23881 (May, Tundo, Ilager, Brandic).
   Multi-objective split-computing (edge/cloud partition + accelerator/CPU
   frequency) optimizer; energy savings vs. cloud-only, architecture- and
   workload-dependent. **Verdict: ignore.** Different mechanism entirely
   (network-layer split point, not token-level decode cost); older paper
   (Oct 2024) already well downstream of what a 2026/2027 venue would
   consider fresh. Noted only to keep the "energy-aware edge scheduling is
   crowded" line in STATUS.md accurate.

4. **CO2-Meter: A Comprehensive Carbon Footprint Estimator for LLMs on Edge
   Devices** — arXiv 2511.08575 (Fu, Fan, Jiang; Indiana University
   Bloomington). Unified operational + embodied carbon estimator; GNN-based
   predictor with **phase-specific (prefill vs. decode) energy modeling**;
   unit-level SoC bottleneck analysis. **Verdict: differentiate-from, mildly
   useful.** The prefill/decode phase split is methodologically adjacent to
   Route A's core claim (VLM = heavy vision-encoder prefill + short LM
   decode changes the constrained-decoding-tax mechanism) — worth a
   related-work citation for the phase-aware energy-modeling approach if
   Route A proceeds, but it's a carbon *estimator/predictor* tool, not a
   study of constrained decoding or grammar masking, so it doesn't compete
   with the actual contribution.

5. **CarbonCall: Sustainability-Aware Function Calling for LLMs on Edge
   Devices** — arXiv 2504.20348 (Paramanayakam, Karatzas, Anagnostopoulos,
   Stamoulis; 2025). Dynamic tool-selection + carbon-intensity-aware power
   scaling + model-size switching for edge function-calling agents; claims
   up to ~50% carbon-impact reduction. **Verdict: differentiate-from.**
   Overlaps with Maria's harness only at the surface level (function/tool
   calling on edge, energy-aware) — the mechanism is *which tool/model to
   call and when*, not the *per-token cost of the grammar mask enforcing the
   call's JSON structure*, which is what G1/Route A actually measures. Cite
   in related work as "adjacent, different layer" if a tool-calling framing
   survives into the final paper.

### Structure/workflow cluster (low relevance, noted for completeness)

6. **Compiling Deterministic Structure into SLM Harnesses (Semantic Gradient
   Descent / SGDe)** — arXiv 2604.17450 (Apr–May 2026). Teacher-student
   compiler that turns agentic workflows into DAGs of LLM calls / deterministic
   code / voting ensembles for small-model deployment; PAC-learning
   convergence bounds; GSM-Hard accuracy gains. **Verdict: ignore.**
   "Structure" here means workflow/DAG topology, not token-level JSON-schema
   grammar constraints — different problem despite the title's echo of
   "deterministic structure."

7. **CL4Health 2026 Dyspnea CRF-filling shared task / "LLM StructCore:
   Schema-Guided Reasoning Condensation and Deterministic Compilation"** —
   arXiv 2604.20560 (Zabolotnii). Two-stage medical Case-Report-Form filling
   (134-item form): Stage 1 LLM produces a 9-key SGR-style JSON summary,
   Stage 2 is a **0-LLM deterministic compiler** that expands it to the full
   134 fields. Macro-F1 0.65 (EN) / 0.69 (IT) on the shared task.
   **Verdict: ignore for the systems paper, note for framing.** This is an
   accuracy-focused clinical-NLP shared-task submission, not a systems paper
   (no edge hardware, no latency/energy, no decoding-cost measurement) — not
   competitive with G1/Route A's contribution. Worth knowing about only as
   evidence that "LLM fills a structured medical form under a schema" is an
   active, real clinical-NLP task shape (CL4Health/LREC-COLING 2026), which
   is mild support for Route A's medical framing having a genuine downstream
   audience — but it does not touch the low-level mechanism question at all.
