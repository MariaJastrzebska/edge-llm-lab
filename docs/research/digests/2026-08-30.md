## Item 1 — Ollama's Apple-Silicon MLX backend: preview → default (baseline-drift watch, re-checked)

This is the assigned angle from iter 22's next action (the general-purpose
inference-engine speedup cluster, stale 6 iterations since iter 16). The
picture has moved since it was last checked in detail:

- **What changed:** Ollama 0.19 (March 2026, tracked since iter 15) was a
  *preview* — MLX-accelerated for exactly one model architecture
  (Qwen3.5-35B-A3B), gated at 32GB+ unified memory. **Ollama v0.30.0
  (May 13, 2026)** promoted MLX from preview to the **default fast path on
  capable Macs**, with llama.cpp's own Metal backend now layered in
  alongside it (auto-routed by file format: safetensors → MLX, GGUF →
  llama.cpp/Metal) so non-qualifying hardware keeps working. By v0.19's own
  spec the MLX runner now covers **six architectures**: Gemma 3, GLM-4 MoE
  Lite, the full Llama series, Qwen 3, Qwen 3.5, and Qwen 3.5 MoE — a real
  widening from "one architecture at preview." Three of G1's four measured
  families (llama3.2:1b, qwen3:0.6b, gemma3:1b) are architecture-eligible
  now; only qwen2.5:0.5b (pre-Qwen3 generation) is not.
- **What didn't change, and is the fact that actually matters for G1:** the
  **32GB+ unified-memory gate is unchanged** across every 2026 source
  checked this iteration (localaimaster.com, modelpiper.com, runaihome.com,
  all independently corroborating each other and the original iter-15
  finding) — Macs with 8GB/16GB stay on the Metal backend with no speed
  change. G1's actual measurement machine (`Marias-MacBook-Air.local`,
  confirmed `ram_total_gb: 16.0` in the `g1-mask-cost-pilot` manifest, iter
  16) is **well under the gate regardless of Ollama version**. Combined with
  iter 16's confirmation that 002–006 ran on Ollama 0.20.6 (pre-dates 0.19
  entirely), this closes the loop cleanly: **no version of Ollama released
  so far — preview, 0.20.6, or the new 0.30.x stable — could have run G1's
  measurements on MLX.** Architecture coverage widening doesn't matter if
  the RAM gate never opens on this hardware.
- **Verdict: watch-not-act, same as iter 15/16, but the "one architecture"
  half of the old caveat is now stale and should be corrected** — it's six
  architectures today, three of them G1's own families. Doesn't change the
  action (still nothing to do), but the old wording ("only one model
  architecture is MLX-accelerated") would mislead if repeated as-is. Fixed
  in STATUS.md's "Known competitive pressure" section this iteration. This
  stays a live watch item only for a **future** re-run on 32GB+ hardware — if
  Maria ever measures on a bigger Mac, the MLX-vs-Metal backend choice
  becomes a real confound to check per-model before trusting numbers.
- Not a paper, no `seen.json` verdict category applies in the cite/build-on/
  differentiate-from/ignore sense — logged as a tracked engine-release event,
  same convention as v0.19 and v0.20.6 before it.
