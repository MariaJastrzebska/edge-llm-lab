### New to seen.json (4 items, all edge-cloud split-computing except one)

1. **CoVSpec** (arXiv 2605.02218) — device-edge co-inference VLM speculative
   decoding (lightweight draft model on the phone, big target model on an
   edge server), 2.21x/1.63x/1.85x speedup over edge-only on
   VQAv2/MMMU/MMBench. **Ignore** — target model never runs on-device, same
   split-computing shape as the standing DynaSplit/Progressive-Semantic-
   Communication line; weakens rather than serves the on-device-privacy
   framing this loop's whole direction depends on.
2. **INAR-VL** (arXiv 2605.18853, TU Wien) — routes "simple" VQA queries to
   an edge-local VLM and "complex" ones to the cloud based on lightweight
   image/text complexity signals; 36% handled on-edge, 24%
   latency/26% energy reduction, 97% of cloud accuracy retained. **Ignore**
   — two-tier split by design, complex queries still leave the device.
3. **LAST** (arXiv 2607.27952) — edge-side compact LLM does one
   decoding-free prefill pass, uses the last query token's attention to pick
   which visual tokens are worth transmitting to a cloud MLLM; order-of-
   magnitude payload/prefill-cost cut, target model stays in the cloud.
   **Ignore** — same split-computing shape as the other two.
4. **Phase Matters** (arXiv 2606.27906, MobiSys Workshop '26) — hardware-
   in-the-loop characterization of VLM inference on a real phone SoC
   (Qualcomm SM8750/Snapdragon 8 Elite), FastVLM-0.5B case study: phase-level
   (prefill vs. decode) NPU/CPU heterogeneity, 100-run thermal stability,
   energy, visual-token-budget sensitivity. NPU gives 1.64x speedup for
   prefill but only 1.18x for decode (**phase-dependent**, matching Ghidorah's
   iter-19 finding that hetero-core speedup isn't uniform across phases);
   2.52x lower energy and 10.47°C lower steady-state temperature overall,
   avoiding thermal throttling in always-on use. **Differentiate-from/cite**
   — no grammar/mask angle, but the strongest edge-VLM characterization-
   methodology precedent found yet (real thermal+energy telemetry, phase-
   level breakdown on real silicon); joins the lm-Meter / Sustainable-LLM-
   Inference-for-Edge-AI instrumentation-citation line.

5. **arXiv 2502.07855** — "Vision-Language Models for Edge Networks: A
   Comprehensive Survey" — taxonomy of edge-VLM design choices (compression,

   healthcare named as one application domain. **Cite** — background/

6. **arXiv 2601.14921** — "Vision-Language Models on the Edge for Real-Time
   Robotic Perception" (Univ. of Leeds) — deploys a VLM on 6G ORAN/MEC
   edge-server infrastructure (WebRTC streaming from a **Unitree G1 humanoid
   robot** testbed), ~5% latency reduction vs. cloud. **Ignore** — edge-
   server split, data still leaves the robot. **Worth flagging: this "G1" is
   Unitree's humanoid product line, unrelated to bigos's own G1 (mask-cost
   tax + shadow-mask pipelining module)** — a second name collision to
   remember (after HARBOR, iter 35) if "G1" ever needs disambiguating in a
   citation search or a conversation with a collaborator.
7. **arXiv 2506.07416** — "LiteVLM" — fully on-device VLM pipeline (camera-
   view patch selection + visual-token selection + speculative decoding) on
   NVIDIA DRIVE Thor for autonomous driving; 2.5x latency reduction (3.2x
   with FP8 PTQ), no accuracy loss. **Differentiate-from** — genuine edge +
   robotics (autonomous driving) VLM optimization, but a different mechanism
   axis than G1 (input-side token/patch pruning + speculative decoding, not
   grammar/mask-cost decoding); no structured/constrained-decoding angle.
8. **arXiv 2603.23640** — "LLM Inference at the Edge: Mobile, NPU, and GPU
   Performance Efficiency Trade-offs Under Sustained Load" — benchmarks
   Qwen2.5-1.5B (4-bit) on Raspberry Pi 5+Hailo-10H NPU, Samsung Galaxy S24
   Ultra, **iPhone 16 Pro**, and a laptop RTX 4050 GPU under 20 sustained
   iterations. iPhone 16 Pro loses ~40% peak throughput within 3 iterations,
   settling into a thermally-throttled plateau (~23.7 tok/s); S24 Ultra
   degrades ~15% into a governor-regulated plateau; the dedicated NPU alone
   stays thermally stable. **Cite, high-value** — text-LLM not VLM, no
   grammar/mask angle, but it directly benchmarks **Maria's own hardware**
   (iPhone 16 Pro) and shows it throttles hard under sustained load — exactly
   the thermal-precondition confound BRIEF.md's paper-grade requirements ask
   every run to record and control for. Directly useful if/when Route A's
   `mtmd` smoke test or any future on-device measurement session happens on
   the iPhone rather than the M1.
